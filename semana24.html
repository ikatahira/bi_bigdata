Zona Abissopelágica (4.000 – 6.000 m)

Um lago onde cabe qualquer formato

No Módulo 2 vocês aprenderam Data Warehouse: um repositório estruturado, com schema definido antes de carregar os dados (schema-on-write). O Data Lake inverte a lógica: guarda os dados brutos, em qualquer formato, e só define a estrutura na hora de ler (schema-on-read) — flexível, mas exige disciplina.

🌊

Data Lake

toque para virar
Repositório que aceita dados estruturados, semi e não-estruturados, sem exigir um schema definido antes de guardar. Barato e flexível.
🏢

Data Lake vs Data Warehouse

toque para virar
DW: schema-on-write, estruturado, otimizado para BI. Data Lake: schema-on-read, aceita qualquer formato, otimizado para explorar e experimentar.
🥉🥈🥇

Camadas (Raw/Trusted/Refined)

toque para virar
Raw: dado exatamente como chegou. Trusted: limpo, validado, padronizado. Refined: agregado, pronto para análise e dashboards.
🐊

Data Swamp

toque para virar
O risco do Data Lake: sem catalogação e governança, ele vira um "pântano de dados" onde ninguém encontra ou confia em nada.

Missão 4 · Construindo seu Data Lake

🏗️ Organize o dataset em camadas

Vocês vão simular um Data Lake usando pastas comuns (no computador ou no Google Drive) — a lógica é a mesma usada em ferramentas reais na nuvem.
  • Crie 3 pastas: raw, trusted e refined.
  • Coloque os CSVs originais do Olist, sem nenhuma alteração, dentro de raw.
  • Crie uma versão em trusted: remova linhas com valores nulos em colunas críticas e padronize os nomes das colunas.
  • Crie uma versão em refined: junte pelo menos 2 tabelas (ex.: pedidos + itens do pedido) numa única tabela pronta para análise.
📝 Entregável: prints das 3 pastas + a tabela final da camada refined.
